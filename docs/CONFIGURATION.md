# Storage and settings

## Download folder

Open **Storage settings > Download folder > Change folder** to choose a location. **Open folder** opens it in Finder or File Explorer. Files are saved in normal filesystem folders; the app’s database keeps their source, status, and location.

A new location applies to newly added items. Existing items keep the location recorded when they were added, including queued items. Changing the folder does not move existing files.

| Environment | Default media location |
| --- | --- |
| macOS | `~/Movies/Reelbox Library/Reelbox` |
| Windows | `Reelbox Library\Reelbox` inside the user’s Videos folder |
| Docker | `Reelbox` inside `DOWNLOAD_HOST_DIR` |

Keep an external drive connected while its items are processing or being opened. Moving files manually breaks their library references. Use **Save a copy** to place a copy in another folder while keeping the managed original available.

## Automatic deletion

The default is **Keep until deleted**. No expiry date is assigned to newly downloaded files with this setting.

Choosing a period schedules deletion for new items, measured from download completion. When the period ends, media files are removed and the task record remains. A separately exported copy is unaffected.

Saving **Keep until deleted** also clears scheduled deletion dates from existing items. Enabling a period again applies to new items; it does not retrospectively add an expiry date to previously preserved files.

## Filename pattern

The default pattern is `{date}_{platform}_{title}_{id}`. Configure it under **Storage settings > Advanced**.

| Field | Value |
| --- | --- |
| `{date}` | Save date in UTC, formatted as `YYYYMMDD` |
| `{platform}` | Platform name |
| `{title}` | Media title |
| `{id}` | Post or media ID |
| `{uploader}` | Creator name |

Characters that are invalid in filenames are replaced with underscores. Per-item folders and an internal unique ID prevent filename collisions. The pattern controls new files and does not rename existing ones.

## Desktop runtime

The desktop app starts the local service and queue automatically. No AI service credentials are required. An internal authentication value is generated at launch to protect communication between the app and its local service; it is unrelated to platform accounts or paid API usage.

Environment variables can be supplied when launching the app from a script:

| Variable | Purpose |
| --- | --- |
| `REELBOX_WORKERS` | Concurrent local tasks; default 3, allowed range 1–6 |
| `REELBOX_USER_DATA_DIR` | Separate app-data directory, including database and sessions |
| `REELBOX_DOWNLOAD_DIR` | Default parent folder for downloaded media |
| `MAX_JOBS` | Task-record capacity; default 50,000, constrained to 2,000–100,000 |

A different app-data directory opens a separate library. It does not move the original library. The repository’s `.env` file is for Docker and is not read by the packaged desktop app.

## Docker environment

Edit `.env` in the repository root, then run `docker compose up -d` to apply changes.

| Variable | Default | Purpose |
| --- | --- | --- |
| `API_TOKEN` | Generated by setup | Shared web-to-API authentication secret, at least 24 characters |
| `WEB_PORT` | `3000` | Local web port |
| `DOWNLOAD_HOST_DIR` | `./downloads` | Media directory on the host |
| `MAX_FILE_BYTES` | `4294967296` | Maximum individual download size: 4 GiB |
| `MIN_FREE_BYTES` | `1073741824` | Minimum free space before saving: 1 GiB |
| `MAX_JOBS` | `50000` | Task-record capacity, constrained to 2,000–100,000 |

The local secret protects service requests. It does not grant access to a social platform or incur API charges. Platform requests still use your internet connection and remain subject to the platform’s access limits.

## Back up a library

Quit the app, then back up **both the app-data directory and every media folder used by the library**. The database alone cannot restore downloaded files.

| Environment | App-data location |
| --- | --- |
| macOS | `~/Library/Application Support/reelbox-desktop` |
| Windows | `%APPDATA%\reelbox-desktop` |
| Docker | `library-data` volume |

Desktop task data is stored in `data/reelbox.sqlite3` beneath the app-data directory. The directory can also contain account sessions and logs; keep this backup private. Restore while the app is closed, and preserve the original media paths so saved records can still find their files.
